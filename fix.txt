 关键发现：**故障机器的 dmesg 中没有 `bonding_dev_0 register success`**，而正常机器有。

这说明 **`bonding_dev_0` 在故障机器上根本没有成功注册到 uburma 驱动中**！

---

## 核心问题

| 正常机器 | 故障机器 |
|---|---|
| `ubcore device: bonding_dev_0 register success` | **无此日志** |
| `primary dev` = `bonding_dev_0` | `primary dev` 指向 `node 1 dev 1 die 0` |
| topo 只有 DEV 0 | topo 有 DEV 0-35 |

**`bonding_dev_0` 注册失败，导致驱动无法找到合法的 primary dev，于是错误地指向了第一个可用的 DEV（即那个异常的 GID 设备）。**

---

## 立即排查 bonding_dev_0 注册失败的原因

### 1. 查看 uburma/ub 模块加载时的完整日志

```bash
# 故障机器
dmesg | grep -i "uburma\|ubcore\|bond\|register\|fail\|error" | head -n 50

# 或更宽泛的搜索
dmesg | grep -i "ub" | head -n 100
```

### 2. 检查 bonding_dev_0 依赖的底层设备

```bash
# 查看 bonding_dev_0 对应的 PCI 设备
readlink -f /sys/class/uburma/bonding_dev_0/device 2>/dev/null
lspci -s $(basename $(readlink -f /sys/class/uburma/bonding_dev_0/device 2>/dev/null)) 2>/dev/null

# 查看该 PCI 设备的状态
cat /sys/class/uburma/bonding_dev_0/device/enable 2>/dev/null
cat /sys/class/uburma/bonding_dev_0/device/vendor 2>/dev/null
cat /sys/class/uburma/bonding_dev_0/device/device 2>/dev/null
```

### 3. 检查 urma2-7 是否能正常注册

```bash
# 查看 urma2 的注册日志
dmesg | grep -i "urma2\|urma.*register" | head -n 20

# 对比 bonding_dev_0 和 urma2 的注册差异
```

### 4. 检查是否有资源冲突

```bash
# 查看内存资源分配
cat /proc/iomem | grep -i "urma\|ub"
cat /proc/ioports | grep -i "urma\|ub"

# 查看中断
cat /proc/interrupts | grep -i "urma\|ub"
```

### 5. 检查模块加载顺序

```bash
# 查看模块加载顺序和时间
dmesg | grep -i "urma\|ub" | grep -i "load\|probe\|init"

# 手动按正确顺序重新加载
sudo modprobe -r urma uburma ub
sleep 2
sudo modprobe ub
sleep 1
sudo modprobe uburma
sleep 1
sudo modprobe urma

# 查看新的 dmesg
dmesg | tail -n 50
```

## 推测

`bonding_dev_0` 注册失败的可能原因：

| 场景 | 说明 |
|---|---|
| **PCI 设备未正确初始化** | qemu 验证时修改了 PCI 配置空间 |
| **内存资源冲突** | bonding_dev_0 需要的 BAR 空间被占用 |
| **中断分配失败** | MSI-X 中断数量不足或配置错误 |
| **固件/BIOS 设置变化** | SR-IOV、ACS 等设置影响设备初始化 |
| **模块加载顺序错误** | ub 模块未正确初始化就加载了 uburma |

---

## 快速验证

```bash
# 1. 检查 bonding_dev_0 的 PCI 设备是否在 dmesg 中有错误
dmesg | grep -i "$(basename $(readlink -f /sys/class/uburma/bonding_dev_0/device 2>/dev/null))" | head -n 20

# 2. 尝试重新扫描 PCI 设备
echo 1 | sudo tee /sys/bus/pci/rescan

# 3. 重新加载模块
sudo modprobe -r urma uburma ub
sudo modprobe ub
sudo modprobe uburma
sudo modprobe urma

# 4. 查看是否有 bonding_dev_0 注册成功
dmesg | grep -i "bonding_dev_0"
```

请先执行 `dmesg | grep -i "ub\|urma" | head -n 100`，看 bonding_dev_0 注册失败的具体错误信息。
