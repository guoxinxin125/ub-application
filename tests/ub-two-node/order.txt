 ### 如果是 buddy_highmem

  说明内核尝试从 node 1 找到连续2 MiB范围，但可能因内存碎片或可借出地址范围不足而失败。

  检查：

  grep -E 'MemTotal|MemFree' \
    /sys/devices/system/node/node1/meminfo

  cat /proc/buddyinfo

  在4 KiB页系统中，连续2 MiB大致对应 order-9。如果 node 1 对应 zone 的高阶空闲块全为0，即使总空闲内存很多，也可能无法分
  配连续2 MiB。

  同时检查内核启动参数：

  cat /proc/cmdline

  重点看是否有：

  pmd_mapping=<比例>%

  buddy_highmem 不只是需要普通空闲内存，还需要能够满足 OBMM 特殊映射属性的物理范围。

  ### 如果是 hugetlb_pmd

  检查 node 1 是否有空闲2 MiB hugepage：

  grep . \
    /sys/devices/system/node/node1/hugepages/hugepages-2048kB/nr_hugepages \
    /sys/devices/system/node/node1/hugepages/hugepages-2048kB/free_hugepages \
    /sys/devices/system/node/node1/hugepages/hugepages-2048kB/resv_hugepages

  如果：

  free_hugepages=0

  那么这是直接原因。

  ## 查看 OBMM node 1 内存池

  for attr in total used available_cleared available_uncleared; do
    attr_path="/sys/kernel/obmm_mempool/obmm-1/$attr"
    if [ -r "$attr_path" ]; then
      printf '%-24s %s\n' "$attr" "$(cat "$attr_path")"
    fi
  done
